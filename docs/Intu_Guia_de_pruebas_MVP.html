Cómo usar esta guía

  1. Empieza por la sección 1: indica qué debe estar listo antes de probar y qué falta hoy.
  2. Sigue las secciones en orden. Cada una deja lista la siguiente (por ejemplo, necesitas un conductor aprobado antes de la sección 7).
  3. En cada prueba marca la primera casilla si pasó (OK) o la segunda si falló (Falla), y anota lo que viste.
  4. 2 teléfonos significa que necesitas al pasajero y al conductor al mismo tiempo. Supabase significa revisar el dato en el dashboard (consultas en el apéndice A).
  5. Si algo falla, sigue el apéndice B para reportarlo con la información que necesito para corregirlo.

1Antes de empezar

1.1 Qué necesitas

  • Dos teléfonos Android (Android 7.0 o superior) con Depuración USB activada: uno para el pasajero y otro para el conductor. Puede ser un teléfono y un emulador, pero el emulador debe tener Google Play para que funcione el login con Google.
  • Dos cuentas distintas: una de pasajero y otra de conductor. Para el conductor usa una cuenta de Google, porque así el correo ya viene verificado y Google ya queda vinculado (ver sección 6).
  • Números de teléfono para el login por SMS, o números de prueba de Firebase (ver el consejo en la sección 3).
  • GPS e internet activos en ambos teléfonos.
  • Acceso a la consola de Firebase y al dashboard de Supabase para revisar datos y aprobar al conductor.

1.3 Instalar la app desde Android Studio

  1. Abre la carpeta Android_Intu y pulsa Sync Project with Gradle Files (ícono del elefante). Espera a que termine sin errores.
  2. En el teléfono, activa Opciones de desarrollador → Depuración USB, conéctalo por cable y acepta el mensaje “¿Permitir depuración USB?”.
  3. Elige el teléfono en la lista de dispositivos de la barra superior y pulsa ▶ Run 'app'.
  4. Para el segundo teléfono, conéctalo, selecciónalo en la misma lista y vuelve a pulsar ▶ Run.
  5. Abre la pestaña Logcat y filtra por package:com.intu.taxi para ver errores mientras pruebas.

¿A dónde quieres ir?→elegir sugerencia→Elegir punto de recojo (opcional)→Confirmar destino→Elige tu viaje→Confirmar viaje→Buscando conductor

Si no eliges un punto de recojo, se usa tu ubicación actual. Requiere sección 1.2

10Problemas conocidos

Los encontré al revisar el código para esta guía. Si los ves, marca la prueba como Falla y escribe “conocido” en Notas: no hace falta investigarlos.

  1. La app se cierra si Supabase rechaza el perfil. En “Guardar y continuar” (4.6) no se maneja el error. Es el más importante mientras falten los pendientes de la sección 1.2.
  2. El saludo del mapa es fijo: siempre dice “¡Hola Carlos!”.
  3. La pestaña Viajes muestra datos de ejemplo (Juan Perez, ABC-123…), no los viajes guardados en Supabase.
  4. “Rechazar” solo oculta la solicitud unos segundos. La app consulta las solicitudes cada 2 s y la vuelve a mostrar.
  5. Tras guardar los datos de conductor, la app entra en modo conductor aunque siga pendiente de aprobación. “Buscar” dará error hasta aprobar la cuenta.
  6. El conductor ve todas las solicitudes de mototaxi abiertas, no solo las cercanas a él.
  7. El pasajero no puede cancelar después de que el conductor aceptó: no hay botón para hacerlo.
  8. Con login por teléfono, “Verificar correo” puede no enviar nada, porque la cuenta de Firebase no tiene correo propio. Solución: vincular Google en Cuenta. Además, tras verificar un correo hay que cerrar sesión y volver a entrar para que la app lo detecte.
  9. Sin la migración MVP, el pasajero no ve moverse al conductor y no se guarda la fecha de confirmación del pago.

AConsultas útiles en Supabase

Dashboard de Supabase → proyecto vkguzpciwpfvaeyedepl → SQL Editor. Pega la consulta y pulsa Run. El uid de cada usuario está en la consola de Firebase → Authentication → Users (columna User UID).

A.1 Perfiles reales (sin los conductores de prueba)

select id, first_name, last_name, phone, email, driver_mode, created_at
from public.profiles
where id not like 'test\_%'
order by created_at desc;

A.2 Últimos viajes

select id, status, rider_name, driver_name, estimated_fare, final_fare,
       payment_method, cancelled_by, requested_at
from public.rides
order by requested_at desc
limit 10;

A.3 Conductores y vehículos

select d.id, p.first_name, p.last_name, d.status, v.brand, v.model, v.plate
from public.drivers d
join public.profiles p on p.id = d.id
left join public.vehicles v on v.driver_id = d.id and v.is_active
where d.id not like 'test\_%';

A.4 Aprobar a un conductor

update public.drivers
set status = 'approved', approved_at = now()
where id = '<uid de Firebase>';

Después, el conductor debe cerrar sesión y volver a entrar en la app.

A.5 Disponibilidad del conductor

select driver_id, latitude, longitude, is_available, updated_at
from public.driver_locations
where driver_id not like 'test\_%';

BCómo reportar un fallo

Para cada prueba que falle, envíame:

  1. Número de prueba (por ejemplo, 7.9) y en qué teléfono pasó: pasajero o conductor.
  2. Qué hiciste, qué esperabas y qué pasó, con la hora aproximada.
  3. Captura de pantalla del error, si se ve.
  4. Logcat: en Android Studio, pestaña Logcat, filtra por package:com.intu.taxi level:error y copia las líneas rojas. Si la app se cerró, busca el bloque que empieza con FATAL EXCEPTION y cópialo completo.
  5. Si el fallo tiene que ver con un viaje, el resultado de la consulta A.2.
